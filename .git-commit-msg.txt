fix(radar): peta device kadang gak tampil tanpa refresh -- root cause bigint-as-string

Ketemu akar masalahnya setelah debug langsung di production (console.log
sementara, sudah dibuang lagi): node-postgres (driver DB dipakai Lucid di
realtime-gateway) secara default mengembalikan kolom BIGINT (id() Laravel
= BIGSERIAL di backend-api) sebagai STRING, bukan number -- beda dengan
Laravel/PHP yang selalu mengembalikannya sebagai number lewat REST API.

Akibatnya device_id yang sama bisa berupa number (lewat REST awal) atau
string (lewat payload socket radar:update/device:status), tergantung
jalur mana yang terakhir menimpa data device di sisi dashboard. Klik
kartu device menyimpan id (kadang string) ke selectedDeviceId, sementara
key di reactive Map tetap number dari load awal -- devices.get() gagal
nemu, peta tidak pernah tampil. "Sembuh" sendiri kalau kebetulan refresh
membuat urutan event jadi konsisten, makanya kelihatan acak/kadang-kadang.

Diperbaiki di dua lapis:
- realtime-gateway/bin/server.ts: pg.types.setTypeParser(20, ...) paling
  atas, sebelum koneksi DB manapun dibuat -- bikin SEMUA kolom bigint di
  gateway konsisten jadi number, bukan cuma device_id (perbaikan di
  sumbernya, bukan cuma ditambal di satu pemakai)
- web-dashboard RadarView.vue: defense-in-depth, device_id dari payload
  socket dipaksa Number() juga sebelum disimpan ke Map, plus :key pada
  iframe peta supaya Vue benar-benar bikin elemen baru tiap ganti device
  (bukan cuma timpa atribut src), dan tombol "Muat ulang peta" buat
  jaga-jaga manual kalau suatu saat Google Maps embed-nya sendiri yang
  bermasalah.

Sudah diverifikasi langsung di app.lacaksmbbot.com (production): klik
device, peta tampil benar isi koordinat sungguhan, diulang 5x berturut
semua berhasil.
